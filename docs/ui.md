# danmubox 前端规格（UI）

> 定位：定义弹幕客户端前端的导航结构、房间页布局、连接状态与手动刷新、消息与身份徽标渲染、礼物栏双模式、输入区与表情面板、举报入口、虚拟列表与滚动、过滤与样式。
> 读者：前端实现者（React + TS）、负责 IPC 与数据层对接的 Rust 侧、验收者。
> 更新时机：新增/修改 IPC 命令或事件（`ipc.md`）、新增 `kind`、调整过滤求值顺序、调整偏好键用法、调整布局断点或待实测校准项时。

本文只描述 UI 层。字段与取值以 [`contract.md`](contract.md) 为准；IPC 命令与事件形状见 [`ipc.md`](ipc.md)；上游协议与发送/举报的实测事实见 [`protocol.md`](protocol.md)；登录与凭据流程见 [`auth.md`](auth.md)；技术栈见 [`decisions/0008-frontend-stack.md`](decisions/0008-frontend-stack.md)。UI **不得**新增 `kind`、字段或偏好键。

**安全红线（契约 §4.1，原样复述）**：`SESSDATA`、`bili_jct`、`DedeUserID` **不得**进日志、不得进前端明文、不得进仓库、不得进崩溃上报。前端只消费 `session_status` 返回的登录态布尔与昵称，永不接触 Cookie 值。

## 1. 技术栈前提

| 项 | 取值 |
|---|---|
| 框架 | React + TypeScript + Vite |
| 虚拟列表 | TanStack Virtual（元素级 `useVirtualizer`） |
| 状态 | Zustand |
| 样式 | CSS Modules（不引入组件库，聊天框自绘） |
| IPC | Tauri 提供的 `invoke` / `listen`（契约 §7 命令与事件） |

不用「行数少时切换为直接渲染」的分支：始终虚拟化，避免两套渲染路径产生行为差异。

## 2. 信息架构与导航

### 2.1 导航结构

导航是两级页面结构：

```
房间列表页 ──(点击房间 / 关注项)──▶ 房间页（可多标签共存）
     ▲                                    │
     └────(返回列表 / 关闭最后一个标签)────┘
```

| 页面 | 内容 | 数据来源 |
|---|---|---|
| **房间列表页** | 正在直播（置顶）、我的房间（手动添加）、关注分组 | `follow_list` / `rooms_list` |
| **房间页** | 标签条、房间头（含「刷新」）、聊天流或「聊天流 + 礼物栏」、输入区 | `history_query` + `danmubox://message` 等事件 |

| 断点 | 宽度 | 房间列表页 | 房间页 |
|---|---|---|---|
| `xs` | < 600px | 独立全屏页面 | 单房间全屏，顶部标签条仍可切换 |
| `md` | 600–1023px | 抽屉（顶栏按钮唤出） | 单房间 + 顶部标签条 |
| `lg` | 1024–1439px | 常驻左栏，可折叠 | 主区 + 顶部标签条 |
| `xl` | ≥ 1440px | 常驻左栏 | 三列（列表 + 主区 + 设置） |

桌面 `lg` / `xl` 下左栏常驻，语义上仍是「房间列表页」的内容；`xs` / `md` 下房间列表是独立页面或抽屉，从房间页返回即回到列表页。

### 2.2 房间列表页

三个区块，自上而下：

| 区块 | 内容 | 排序 |
|---|---|---|
| 正在直播 | `follow_list` 与 `rooms_list` 中 `live_status == 1` 的并集 | 置顶（契约 §5 `FollowedRoom`），组内保持上游返回顺序 |
| 我的房间 | `rooms_list`（手动添加，`rooms_add`）中非直播中的房间，带删除按钮（`rooms_remove`） | 上游返回顺序 |
| 关注分组 | `follow_list` 中非直播中的项，按 `group_name` 分组折叠 | 分组内上游返回顺序，前端不重排 |

- `live_status` 展示映射：`1` → 「直播中」（强调色）、`2` → 「轮播中」（弱化）、`0` → 「未开播」（弱化）。
- 关注列表中的房间点击即**进场**（打开房间页），不写入 `rooms_list`；「我的房间」的项才走 `rooms_add` / `rooms_remove`。
- 「刷新关注」按钮调用 `follow_list`，刷新期间按钮禁用并显示转圈；失败时保留旧列表并提示原始错误文本。
- 手动添加：输入短号 / URL / 房间号 → `rooms_add`；房间不存在时提示「房间不存在或短号无效」并保留输入。
- 列表项展示头像（`face`）、昵称（`uname`）、真实房间号（`room_id`）、直播状态标签、分组名。

### 2.3 房间页与多标签

```
房间页（`xl`，礼物栏 `merged`；左栏 = 房间列表页内容，可折叠）
┌──────────────────┬──────────────────────────────────────────┬──────────────┐
│ danmubox      ●  │ [● 1号房 ×][○ 2号房 ×][ + ]        [↻][⚙]│ 外观         │
├──────────────────┼──────────────────────────────────────────┼──────────────┤
│ 正在直播         │ 1号房主播 · 直播中 · 人气 12,340  ● 已连接│ 字号 ●━━━ 大 │
│  ● 1号房         ├──────────────────────────────────────────┤ 透明度 ━● 1.0│
│  ● 2号房         │ 00:12:04  弹 [舰5][🎖] 张三：前方的路…   │ 主题 跟随系统│
│                  │ 00:12:05  入  李四 进入了直播间          │ 合并相似 [开]│
│  我的房间        │ 00:12:05  礼  王五 投喂 小心心 ×3        │ 礼物栏 合并 ▾│
│  ○ 3号房         │ 00:12:06  舰  钱七 开通 舰长             │ 过滤         │
│                  │ 00:12:07  系  —— 房间标题已更新 ——       │ 关键词 ──────│
│ [ + 添加房间 ]   │                                          │ 用户 ────────│
│                  │            [ ③ 条新消息 · 回到最新 ]     │ 牌级 ≥0      │
│                  │                                          │ 类型 ☑弹幕…  │
│                  │ ┌──────────────────────────────────────┐ │ 账号 已登录  │
│                  │ │ 说点什么…                    [😀][📤] │ │ 退出登录     │
│                  │ └──────────────────────────────────────┘ │              │
└──────────────────┴──────────────────────────────────────────┴──────────────┘
```

| 项 | 规则 |
|---|---|
| 标签条 | 已打开房间的标签，按打开顺序排列，可横向滚动；激活标签高亮，连接状态点见 §3 |
| 多标签共存 | 已打开的房间保留各自的长连接与**会话缓冲**；切换标签只切换渲染，不断开、不清空 |
| 新增标签 | 在房间列表点击房间：已打开则激活该标签，未打开则新开 |
| 关闭标签 | 关闭该房间页，断开连接、销毁并清空该房间的会话缓冲；**不**删除房间数据（不调 `rooms_remove`） |
| 返回列表 | `xs` / `md` 下从房间页返回列表页，等同于关闭当前房间页 |
| 标签数量 | 不做硬上限；超过可视宽度横向滚动，不折叠为下拉 |
| 溢出标签 | 非激活标签不入渲染队列；连接与该房间的会话缓冲照常保持 |

### 2.4 会话缓冲生命周期（契约 §4.3）

弹幕只在**内存环形缓冲**中保留，生命周期 = **一次房内会话**。

| 动作 | 会话缓冲 | 长连接 | 说明 |
|---|---|---|---|
| 进入房间（打开标签） | 新建，空，`local_id` 从 1 开始 | 建立 | 开始一次新会话 |
| 切换标签 | 保留 | 保持 | 不算离开房间 |
| 点击「刷新」（`rooms_reconnect`） | **保留**，不清空 | 重连 | 仍属同一次会话 |
| 返回列表页 / 关闭标签 | **销毁并清空** | 断开 | 会话结束 |
| 再次进入同一房间 | 全新会话，从空开始 | 新建 | 不复用上一次会话的缓冲 |

- 缓冲上限 5000 条（`history.buffer_rows`，契约 §8），超出丢最旧；进程退出即丢。
- 会话内允许向上回滚查看（`history_query`）；B 站无历史回放接口，本设计不做跨会话历史，也没有向前翻取更早内容的入口。

## 3. 房间头与连接状态

### 3.1 房间头

房间头固定在聊天流上方（不参与虚拟列表滚动）：

| 元素 | 取值与来源 |
|---|---|
| 昵称 / 房间号 | 房间元信息（`follow_list` / `rooms_list` / `getRoomPlayInfo` 解析结果） |
| `live_status` | `0` 未开播 / `1` 直播中 / `2` 轮播；**只展示状态标签** |
| 人气值 | `op=3` 心跳回应的 4 字节大端整数（契约 §6），失败或未知时显示 `—` |
| 会话时长 | 本次房内会话已持续的时长，每秒更新；离开房间即消失 |
| 刷新按钮 | 见 §3.2 |
| 状态点 | 见 §3.3 |

### 3.2 「刷新」按钮（手动重连）

用途：长连接卡住、推流暂时中断、或长时间无新消息时**手动重连**。命令为 `rooms_reconnect`（契约 §7）。

| 项 | 规则 |
|---|---|
| 位置 | 房间头最右，文案「刷新」，图标 `↻`，始终可见 |
| 触发 | `invoke('rooms_reconnect', { roomId })` |
| 效果 | 立即断开并按退避序列重新建立连接；**保留**已收消息与滚动位置，不清空会话缓冲 |
| 状态反馈 | 触发后状态点立即变 `connecting`；成功转 `connected`，失败转 `error` 并继续退避 |
| 连续点击 | 处于 `connecting` 时按钮禁用（见下表），避免并发重连 |
| 与自动重连的关系 | 手动触发会**清零退避计数**，即立刻重试而不是等下一个退避档 |
| 断线期间消息 | 重连成功后的消息继续追加到同一缓冲；断线期间的空档不回填 |

### 3.3 连接状态与按钮可用性

四种连接状态由 `danmubox://room` 与 `danmubox://status` 事件驱动：

| 状态 | 状态点视觉 | 房间头文本 | 「刷新」按钮 | 说明 |
|---|---|---|---|---|
| `connecting` | 黄色实心圆，1s 呼吸动画 | 「连接中…」 | **禁用**，显示加载态 | 连接请求已发出、认证未完成 |
| `connected` | 绿色实心圆，不跳动 | 「已连接」 | **可用** | 长连接正常；卡住时用户手动刷新 |
| `disconnected` | 灰色空心圆 | 「已断开」 | **可用** | 未连接或已主动断开；点击立即重连 |
| `error` | 红色实心圆 | 「连接失败，第 N 次重试，Xs 后重试」 | **可用** | 认证失败或上游错误，正在退避重连 |

规则：

1. 退避序列按契约 §4 为 **5s / 10s / 20s / 40s / 60s 封顶**；倒计时数字每秒更新，显示为房间头横幅的一部分。
2. 认证被拒（`code != 0`）一律视为认证失败并按退避重连；**不得**在未知 code 上编造含义，横幅只显示原始 code。
3. 状态点同时出现在对应标签页上（同一套视觉），便于多标签下判断哪个房间需要刷新。

## 4. 消息渲染

### 4.1 六种 `kind` 的视觉规范

`kind` 取值只有契约 §5 的六种。字号档基准见 §8.2，行高由内容折行实测（§7.1），不冻结固定值。

| kind | 颜色（本地设计 token） | 图标位 | 对齐 | 字号档 | 备注 |
|---|---|---|---|---|---|
| `danmaku` | 行首竖条取消息 `color`（十进制 RGB → `#RRGGBB`）；`color = 0` 时用 `--fg-muted`；正文用默认前景色 | `弹` | 左对齐 | 正文档 / 昵称低一档 / 时间最低档 | 竖条贴行首，仅此一种取消息颜色 |
| `gift` | 竖条 `--gold #C08A2E`；礼物名加粗；`amount` 用金额色 | `礼` | 左对齐 | 正文档 / 昵称低一档 | 金额单位见 §6.4、§13 |
| `superchat` | 卡片，背景与边框取自 SC 档位 token `--sc-1 … --sc-5`（档位边界见 §13）；金额行加粗 | `SC` | 左对齐，卡片占满行宽 | 金额低一档加粗 / 正文档 / 昵称低一档 | 高度随内容行数增长 |
| `interact` | 竖条 `--neutral #6B7280`；正文 `--fg-muted` | `入` | 左对齐 | 最低档 | 弱化显示，见 §8.3 |
| `guard` | 竖条按 `guard_level`：1 总督 `--guard-1 #C0392B` / 2 提督 `--guard-2 #8E44AD` / 3 舰长 `--guard-3 #2980B9`；`0` 用中性色 | `舰` | 左对齐 | 正文档加粗 / 昵称低一档 | 文案见 §13 |
| `system` | 无竖条；文本 `--fg-subtle` | `系`（居中时可省略） | 整行居中 | 最低档 | 由 `core` 归一化后的系统事件 |

色值为本项目本地设计 token，与 B 站网页端配色的差异见 §13。

表情弹幕（`Message.emote_url` 非空）**画图不画字**：此时正文就是表情名，只显示文字会被当成「表情没渲染」。图片与文字同高对齐（约 26px），`alt` 与 `title` 都填表情名——图加载不出来时浏览器回退显示 alt，不至于变成空白。**一切来自上游 CDN 的图片都必须在无 Referer 的前提下请求**（`index.html` 的 `<meta name="referrer" content="no-referrer">`）：该 CDN 有防盗链，非 bilibili 来源返回 403，浏览器再以 ORB 拦掉，表现为整屏问号且控制台毫无线索。

### 4.2 身份徽标

徽标只从契约 §5 的既有字段派生，**不新增字段**：

| 徽标 | 派生条件 | 视觉 | 优先级 |
|---|---|---|---|
| 主播 | `uid == Room.anchor_uid`（由房间解析得到的 `uid`，**不是** `Message` 字段） | 红色圆角标「主播」，白字 | 1（职衔槽最高） |
| 房管 | `Message.is_admin == true` | 蓝色圆角标「房管」，白字 | 2 |
| 总督 | `guard_level == 1` | 金红渐变圆角标「总督」 | 3（大航海槽最高） |
| 提督 | `guard_level == 2` | 紫色圆角标「提督」 | 4 |
| 舰长 | `guard_level == 3` | 蓝色圆角标「舰长」 | 5 |

**两个槽位 + 并列规则**：

| 槽位 | 容纳 | 互斥规则 |
|---|---|---|
| 职衔槽（昵称左侧第一槽） | 主播、房管 | 二者互斥，**主播优先**：`uid == anchor_uid` 为真时即使 `is_admin` 也为真，只渲染主播徽标 |
| 大航海槽（职衔槽右侧） | 总督、提督、舰长 | `guard_level` 是单值，天然至多一枚 |

- 两个槽位**可并列**：如「房管 + 舰长」同时渲染；「主播 + 总督」也允许（上游字段允许时）。
- 主播与房管不得同时出现（同一人）；`uid == anchor_uid` 时忽略 `is_admin`。
- 徽标顺序固定为 `[职衔槽][大航海槽][粉丝牌]`，昵称紧随其后；徽标是**昵称前置**元素，不占用行首竖条。
- 点击昵称（含徽标区域）在系统浏览器打开该用户主页；`uid == 0`（游客/未知）时昵称不可点击。

### 4.3 字段使用

| kind | 使用的 `Message` 字段 |
|---|---|
| `danmaku` | `ts` `uname` `content` `color` `medal_level` `medal_name` `guard_level` `is_admin` `uid` |
| `gift` | `ts` `uname` `content`（礼物描述） `amount` `uid` |
| `superchat` | `ts` `uname` `content` `amount` `uid` |
| `interact` | `ts` `uname` `content`（行为描述） `uid` |
| `guard` | `ts` `uname` `content` `guard_level` `amount` `uid` |
| `system` | `ts` `content` |

统一规则：`uid == 0` 且 `uname` 为空时昵称显示「游客」；`medal_level == 0` 不渲染粉丝牌；`guard_level == 0` 不渲染大航海徽标；`color` 解析失败（越界或非法十进制）回退默认前景色，不抛错。

### 4.4 本地发送回显与被吞标记

本地发送的弹幕按 `SendOutcome`（契约 §5）决定回显，避免与上游回推重复：

| `SendOutcome` | 是否本地回显 | 行内标记 |
|---|---|---|
| `ok` | **不**回显（等上游通过 `danmubox://message` 回推，避免重复） | 无 |
| `blocked_platform` | 回显一条 `danmaku` 行 | 整行**红色**删除线 + 行尾红色角标「平台未展示」 |
| `blocked_room` | 回显一条 `danmaku` 行 | 整行**黄色**删除线 + 行尾黄色角标「直播间未展示」 |
| `rate_limited` / `medal_required` / `muted` / `failed` | **不**回显（消息未发出） | 提示文案见 §6.5，草稿按 §6.1 保留 |

被吞标记规则（参考社区脚本「Bilibili Live Banned Danmaku Marker」的判定思路，判定来源见 `protocol.md`）：

| 判定 | 判定值 | 竖条 | 文本 | 角标 | 悬浮说明 |
|---|---|---|---|---|---|
| 平台吞（风控） | 上游 `msg` / `message` == `"f"` | 红色 `--block-platform #D93025` | 删除线 + 弱化 | 「平台未展示」 | 「该弹幕未出现在公开弹幕流（平台侧处置）；内容已回显在响应 `data.mode_info.extra`」 |
| 直播间吞（主播/房管） | 上游 `msg` / `message` == `"k"` | 黄色 `--block-room #F0A020` | 删除线 + 弱化 | 「直播间未展示」 | 「该弹幕被本直播间处置（主播或房管）」 |
| 其他失败 | 其余 code | 不产生行 | — | — | 走 §6.5 文案表 |

- 只有本人发送的弹幕才带被吞标记；他人消息不产生该标记。
- 标记为会话内状态，不落盘；离开房间即消失。

### 4.5 行悬浮菜单

鼠标悬停（桌面）或长按（触控）任意消息行，弹出菜单：

| 菜单项 | 可用条件 | 行为 |
|---|---|---|
| 复制内容 | `content` 非空 | 写入剪贴板，toast「已复制」 |
| 复制昵称 | `uname` 非空 | 写入剪贴板 |
| @TA | `uname` 非空且消息来自他人 | 向输入区插入 @ 文本（见 §6.2） |
| 回复 | 同上 | 输入区显示引用条（昵称 + 内容摘要），发送语义见 §6.2 |
| 屏蔽此用户 | `uid != 0` | 把 `uid` 追加进 `filter.uids`（契约 §8），列表即时过滤 |
| 打开主页 | `uid != 0` | 系统浏览器打开用户主页 |
| **举报** | 已登录且 `upstream_id` 非空 | 打开举报弹层，见 §4.6 |

`upstream_id` 为空或未登录时「举报」置灰，`title` 说明原因（「缺少上游标识，无法举报」/「需登录后举报」）。

### 4.6 举报（`chat_report`）

| 项 | 规则 |
|---|---|
| 入口 | 行悬浮菜单「举报」（§4.5） |
| 弹层内容 | 举报理由**单选列表**（必选）+ 「提交」「取消」 |
| 理由清单 | **不在 UI 写死文案**：按上游/适配器暴露的理由枚举渲染；理由 id 与文案的对应关系见 §13「待实测校准」，实测前只渲染适配器返回的项 |
| 提交 | `invoke('chat_report', { roomId, upstreamId, reasonId })` |
| 成功 | 弹层关闭，该行加**本地标记**「已举报」（灰色小旗角标 + 行底轻微底纹），同 `upstream_id` 禁止重复举报（菜单项变为「已举报」且禁用） |
| 失败 | 弹层保持打开，显示原始 code 与 message，允许重试；不改写上游语义 |
| 标记生命周期 | 仅**会话内**有效，不落盘；离开房间即清除 |
| 未登录 | 入口置灰（§4.5），不做本地模拟举报 |

### 4.7 进场回填的历史弹幕

进入房间时，服务端可能先铺一批「最近的弹幕」（上游上限 10 条普通 + 10 条房管，**不可翻页**，见 `protocol.md` 附录 A30；语义见 `contract.md` §4.3）。

| 项 | 规则 |
|---|---|
| 判定 | `Message.is_history == true`（契约 §5）；实时推来的恒为 `false` |
| 呈现 | 整行降低不透明度（0.55），与实时弹幕一眼可分 |
| 分界 | 历史与实时之间由**第一条实时消息**上方的虚线 + 说明文字「以上为进场前的最新弹幕」标出，不为分界线单独占一行 |
| 交互 | 与普通弹幕完全一致：过滤、合并、悬浮菜单、举报都照常（回填已带 `upstream_id`） |
| 取不到时 | 上游可能返回空（见 A30）——此时房间就与从前一样从空列表开始，**不得提示错误、不得重试风暴** |

## 5. 礼物栏双模式（`ui.gift_panel_mode`）

`ui.gift_panel_mode`（契约 §8）取值 `merged` / `separate`，默认 `merged`。

| 模式 | 含义 | `gift` / `guard` 的渲染位置 |
|---|---|---|
| `merged` | 礼物**混在弹幕栏** | 直接作为 `gift` / `guard` 行插入聊天流，按 §4.1 渲染 |
| `separate` | **独立礼物栏** | 聊天流不再渲染 `gift` / `guard`；两类消息改在独立礼物栏渲染 |

两种模式都受 `filter.kinds` 白名单支配：白名单移除 `gift`（或 `guard`）时，**两处都不渲染**。

## 6. 输入区

### 6.1 布局与草稿

输入区自上而下：引用条（有回复上下文时出现，带「取消」）→ 文本输入框 → 右下角操作组（电池余额、表情、@、发送）。

| 项 | 规则 |
|---|---|
| 文本框 | `<textarea>`，自适应 1–5 行，超出内部滚动；`Enter` 发送、`Shift + Enter` 换行为默认行为，不可配置 |
| 发送按钮 | 有明确文本「发送」，不用纯图标；发送中显示节流倒计时（本地最小间隔 2s，契约 §4） |
| 草稿保留 | 每个房间的草稿按 `room_id` 存在前端 store，**会话内**保留（切换标签不丢、返回列表则随会话销毁）；**不写入** `prefs.json`（契约 §8 无对应键） |
| 发送后 | `ok` 时清空文本框；失败时按 §6.5 **保留草稿**并把失败原因显示在输入区上方 |
| 长度提示 | 超过上游长度上限时，发送按钮禁用并显示计数；上限值见 §13 |

### 6.2 短语与 @

| 功能 | 规则 |
|---|---|
| 内置快捷短语 | 编译期常量表（常用语 + 颜文字），不占偏好键；点选插入光标处 |
| 自定义短语 | 用户新增/删除，**会话内**保存（同草稿，不落盘）；每条短语可命名并在面板中列出 |
| 颜文字 | 归入内置快捷短语分组，独立一个「颜文字」标签页 |
| @某人 | 行菜单「@TA」把 `@昵称 ` 插入光标处；上游是否支持 at 语法与 at 后是否真正提醒见 §13，UI 不保证提醒效果 |
| 回复 | 行菜单「回复」后在输入区上方显示引用条（昵称 + 内容摘要）；发送时按上游支持的 at 语法拼装文本（`Message` 无引用字段，本地不渲染引用结构）；取消引用则清空引用条，草稿文本不变 |
| 最近发送 | 输入框内按 `↑`（焦点在文本框且光标在首行时）回填最近一次发送内容，仅会话内保存 |

### 6.3 表情面板（`emotes_list`）

按**当前房间身份**加载（`RoomSession`，契约 §5）：`my_medal_level` / `my_medal_name` / `my_guard_level` / `is_admin`。面板结构：搜索框 → 身份分组标签 → 表情网格（纵向滚动）。

| 分组（`package_kind`） | 可见条件 | 说明 |
|---|---|---|
| 通用 `common` | 始终可见 | 全站通用表情（实测 `pkg_type = 1`） |
| 本房间 `room` | 始终可见 | 房间专属表情（实测 `pkg_type = 2` 且表情无解锁门槛）；房间没有这类表情时不渲染该标签 |
| 粉丝牌 `medal` | `RoomSession.my_medal_level > 0` | 我在**该直播间**的粉丝牌档位表情（实测：包内 `unlock_need_level > 0` / `identity ∈ 1..4` 即归此组，与包名无关）；无牌时不渲染该分组标签 |
| 大航海 `guard` | `RoomSession.my_guard_level ∈ {1, 2, 3}` | 按当前大航海等级可用集合；未开通时不渲染该分组标签 |
| 房管 `admin` | `RoomSession.is_admin == true` | 房管专属表情；非房管时不渲染该分组标签 |

| 项 | 规则 |
|---|---|
| 打开 | 输入区「😀」按钮；再点关闭；打开时保持输入框焦点与草稿 |
| 分组标签 | 只渲染当前身份可用的分组；身份变化（进不同房间）时重建分组并回到「通用」 |
| 网格 | 桌面 8 列、窄屏 6 列；纵向滚动，长列表虚拟化或分页加载 |
| 搜索 | 按 `Emote.text` 做 Unicode 大小写折叠的子串匹配；无结果时显示「没有匹配的表情」 |
| 插入 | 点击表情把 `Emote.text` 插入文本框光标处（`text` 即文本弹幕内容）；面板**不自动关闭**，支持连续插入 |
| 图片 | 单元格按 `Emote.url` 展示缩略图；图片加载失败时回退显示 `Emote.text` 文本；不因图片失败阻断插入 |
| 房间专属 | `Emote.room_id != 0` 的表情只在对应房间展示（`room_id` 与当前房间一致） |
| `key` | 仅用于列表 key 与去重，不展示 |
| 空态 | 分组返回空列表时显示「该分组暂无可用表情」 |

### 6.4 电池余额（`wallet_balance`）

| 项 | 规则 |
|---|---|
| 位置 | 输入区操作组内，图标 + 数值 |
| 刷新时机 | 进入房间时、每次送礼成功后、点击数值手动刷新 |
| 未登录 | 显示「—」，`title`「登录后可见」 |
| 失败 | 显示「—」并保留上一次成功值 5 秒后回退，不弹窗 |
| 单位 | 数值直接展示，单位与换算见 §13 |

### 6.5 发送结果与失败文案

`chat_send` 返回 `SendOutcome`（契约 §5，七个取值）。发送到结果返回前的等待期，发送按钮显示节流倒计时并禁用。

| `SendOutcome` | 含义 | UI 文案 | 位置 | 草稿 | 回显 |
|---|---|---|---|---|---|
| `ok` | 已发出并进入公开弹幕流 | 无（静默） | — | 清空 | 不本地回显，等上游回推 |
| `blocked_platform` | 被平台风控吞掉 | 「已发送，但未出现在公开弹幕流（平台侧处置）」 | 输入区上方横幅 + 行内标记（§4.4） | 清空 | 红色删除线回显 |
| `blocked_room` | 被直播间吞掉 | 「已发送，但被本直播间处置（主播或房管）」 | 输入区上方横幅 + 行内标记（§4.4） | 清空 | 黄色删除线回显 |
| `rate_limited` | 频率限制 | 「发送过于频繁，请稍后再试」+ 倒计时（本地最小间隔 2s，契约 §4） | 输入区上方横幅 | **保留** | 不回显 |
| `medal_required` | 粉丝牌等级不足 | 「本直播间需粉丝牌等级达标才能发言」 | 输入区上方横幅 | **保留** | 不回显 |
| `muted` | 已被禁言 | 「你已被禁言（全局或本直播间）」 | 输入区上方横幅 | **保留** | 不回显 |
| `failed` | 其他失败 | 「发送失败」+ 原始 code 与 message | 输入区上方横幅 + 「重试」按钮 | **保留** | 不回显 |

规则：

1. 文案**不猜测**上游细节；`failed` 必须展示上游原始 code 与 message，不改写语义。
   上游原话与 code 由 `chat_send` 返回的 `detail` 字段携带（契约 §5 `SendReport`），
   界面直接拼接显示，例如「发送失败 · 发送失败，请先移除该用户黑名单（code 10023）」。
2. 除 `ok` / `blocked_*` 外一律保留草稿，用户可直接重试。
3. 横幅自动消失时间为 5s（`failed` / `muted` 常驻直到用户操作或修改草稿），用户可手动关闭。
4. 被吞判定（`"f"` / `"k"`）由适配器归一化，UI 只消费 `SendOutcome`，不做字符串判定。
5. 游客未登录时发送按钮禁用，`title`「需登录后发送」。

## 7. 虚拟列表、自动滚动与暂停

### 7.1 虚拟列表

使用 TanStack Virtual 的元素级 `useVirtualizer`，滚动容器是聊天流自身的 `<div>`（不是 `window`），保证桌面与 Android WebView 的滚动/惯性一致，并允许房间头与输入区独立于滚动。

| 参数 | 取值 | 说明 |
|---|---|---|
| `count` | 过滤与合并后的可见行数 | — |
| `getScrollElement` | 聊天流容器 ref | 元素级虚拟化 |
| `estimateSize` | 按 `kind` 基准行高 × `ui.font_scale` 估算 | 实际高度由 `measureElement` 写回 |
| `getItemKey` | `local_id`；合并行取行内首条消息的 `local_id` | 契约 §5：`local_id` 仅用于 UI key 与本地引用 |
| `overscan` | 12（窄屏 8） | 真机不达标时按 §13 下调 |
| `measureElement` | 开启 | 动态行高实测写回 |
| `scrollToFn` | 自定义 | 跟随模式瞬时定位（§7.3） |
| `lanes` | 1 | 单列 |

行高与动态处理：

| 场景 | 处理 |
|---|---|
| 内容折行 | 按容器宽度折行；超过 4 显示行时截断，行尾给「展开」，展开状态为行本地 state，不写入 store |
| 长昵称 | 昵称截断到 8 字符 + `…`；完整昵称放 `title` |
| 粉丝牌 | 最多 6 字符，超出截断；等级数字最多 3 位 |
| `rowScale` | 即 `ui.font_scale` 当前值（§8.2） |
| 图片 / 表情 | 消息正文不加载远程图片（表情图片只在表情面板按需加载，见 §6.3） |
| `ResizeObserver` | 容器宽度变化（抽屉开合、窗口缩放）触发重新测量，并在同一帧内恢复锚点 |
| 字体 | 只用系统字体栈，避免字体加载完成后行高跳变 |

### 7.2 自动滚动与暂停

| 状态 | 进入条件 | 行为 | 退出条件 |
|---|---|---|---|
| 跟随最新 `following` | 进入房间且 `ui.auto_scroll = true`；点击「回到最新」；滚动到距底 ≤ 8px | 每次 flush 后定位到列表底部；隐藏「回到最新」 | 距底 > 8px |
| 用户暂停 `paused` | 上滑 / 拖动滚动条使距底 > 8px | 冻结视口位置；新消息不改动 `scrollTop`；显示「N 条新消息 · 回到最新」 | 点击「回到最新」；滚回距底 ≤ 8px |
| 悬停暂停 `hovered` | `ui.pause_on_hover = true` 且鼠标进入聊天流区域 | 与 `paused` 相同的冻结行为，但不显示「回到最新」 | 鼠标离开后回到进入前的状态；触控设备不进入该状态 |
| 非激活标签 `background` | 该房间不是当前标签 | 不入渲染队列；连接保持、会话缓冲照常追加 | 切回该标签 |

规则：

1. 距底阈值 8px 是唯一判定依据，不用滚动方向启发式（手势惯性下会抖动）。
2. 初始状态由 `ui.auto_scroll` 决定；用户暂停/恢复时把新状态写回 `ui.auto_scroll`，作为下次进入房间的初始值。
3. 独立礼物栏（`separate` 模式）各自维护跟随状态，互不影响。
4. 「回到最新」使用平滑滚动。
5. `visibilitychange` 为 hidden 时不依赖 rAF（后台会被节流），改为 1s 定时批量写入 store，恢复可见时立即 flush 并对齐滚动。

### 7.3 滚动锚定

| 变更类型 | 锚定方式 |
|---|---|
| 尾部追加新消息 | 保持 `scrollTop`；跟随模式下在帧末尾定位到底部；非跟随模式不做位移 |
| 过滤条件变更 | 记录变更前首个可见行的 `local_id` 与其视口偏移，变更后 `scrollToIndex(key, { align: 'start' })` 并按偏移微调 |
| 合并把 N 行折叠为 1 行 | 同「过滤条件变更」，锚点取合并行首条消息的 `local_id` |
| 字体档位变更 / 抽屉开合 / 宽度变化 | 清空高度缓存并重新测量，锚定行保持视口内位置 |
| 手动刷新重连 | 不改变 `scrollTop`，不重排列表（会话缓冲未变） |
| 跟随模式定位 | 直接设置 `scrollTop = scrollHeight`，不使用平滑滚动 |

### 7.4 「回到最新」按钮

| 项 | 规则 |
|---|---|
| 显示条件 | 状态为 `paused` 且新消息计数 ≥ 1 |
| 文案 | `N 条新消息 · 回到最新`，N > 999 显示 `999+` |
| 位置 | 桌面：聊天流右下角；窄屏：输入区上方，水平居中 |
| 层级 | 浮于列表之上，不参与虚拟列表布局，不占行 |
| 点击 | 恢复 `following`（§7.2）并按规则 4 定位 |

## 8. 过滤、样式与合并

### 8.1 过滤（`filter.*`）

| 维度 | 偏好键 | 形态 | 匹配规则 | 求值顺序 |
|---|---|---|---|---|
| 消息类型 | `filter.kinds` | 六种 `kind` 多选白名单 | 未列入白名单的 `kind` 不渲染、不参与合并 | 1 |
| 粉丝牌等级 | `filter.medal_level_min` | 数值下限（0 不限） | `medal_level` 小于该值的消息丢弃；阈值 > 0 时无牌（`medal_level == 0`）消息一并丢弃 | 2 |
| 用户 | `filter.uids` | UID 屏蔽列表 | 精确匹配 `uid`；`uid == 0` 的游客不参与匹配 | 3 |
| 关键词 | `filter.keywords` + `filter.keywords_mode` | 关键词列表 + 模式 | 对 `content` 做 Unicode 大小写折叠后子串匹配；多个关键词之间为 OR；`hide` 命中即丢弃，`only` 未命中即丢弃 | 4 |

求值顺序固定为 1→4，通过后进入合并（§8.4）再进入虚拟列表。第 2 步只作用于 `danmaku` / `gift` / `guard`；`superchat` / `interact` / `system` 不受 `filter.medal_level_min` 影响。

- 付费消息保底：`superchat` 与 `guard` 在类型白名单中的开关**必须**保留在设置面板上，但允许用户取消；取消后列表顶部显示一次性提示条「已隐藏付费消息」，可撤销。
- `filter.kinds` 为空数组时列表恒为空，显示「全部消息被过滤」空态并提供「恢复全部类型」按钮（写回六种 `kind` 全集）。
- `ui.gift_panel_mode = separate` 时，`gift` / `guard` 的渲染位置变为礼物栏，但白名单语义不变（移除即两处都不渲染）。
- 关键词告警：`filter.keywords_alert = true` 时，命中关键词的消息高亮并在命中时提示（契约 §8），隐藏模式同理只作用于命中项。

### 8.2 字号

`ui.font_scale` 为 number，范围 0.8–2.0，默认 `1.0`。滑杆给出四个命名预设（不引入额外键名）：

| 档位（预设） | `ui.font_scale` |
|---|---|
| 紧凑 | 0.86 |
| 标准（默认） | 1.00 |
| 舒适 | 1.14 |
| 大 | 1.29 |

所有字号 = 标准档基准（正文 14px）× `ui.font_scale`，向上取整到整数像素；昵称、时间与徽标各低一档。滑杆取非预设值时不吸附到预设。变更后清空高度缓存并按 §7.3 重建锚点。

### 8.3 透明度与主题

| 对象 | 默认不透明度 | 说明 |
|---|---|---|
| `danmaku` / `gift` / `superchat` / `guard` | 1.0 | 正文不透明 |
| `interact` | 0.6 | 弱化 |
| `system` | 0.7 | 弱化、居中 |
| 整体列表（`ui.opacity`） | 1.0，可调 0.3–1.0 | 作用于列表容器，叠乘到上面每类取值；不改变消息 `color` |

`ui.opacity` 低于 0.6 时设置面板给出「对比度可能不足」的文字提示，但不强制限制。主题由 `ui.theme` 决定，取值 `system` / `dark` / `light`，默认 `system`；六种 `kind` 的颜色 token 在明暗两套取值下分别定义，切换主题即换 token，不改变 `kind` 语义。

### 8.4 合并相似消息

由 `ui.merge_similar`（默认 `true`）开关，窗口基准值为 `ui.merge_window_ms`（integer，默认 `8000`）。各 `kind` 的窗口 = 基准值 × 下表倍率，倍率为本地渲染规则，不占独立偏好键。

| kind | 合并键 | 窗口倍率 | 默认窗口（基准 8000ms） | 合并后展示 |
|---|---|---|---|---|
| `danmaku` | room + uid + uname + medal_name + medal_level | ×1 | 8s | `昵称：内容 ×N（首末时间）[展开]` |
| `gift` | room + uid + 礼物名 | ×2 | 16s | `昵称 投喂 礼物 ×N 共 amount`（连击聚合） |
| `superchat` | 不合并 | — | — | 每条独占卡片 |
| `interact` | room + uid + 行为类型 | ×1 | 8s | `N 人进入直播间` 同行聚合 |
| `guard` | room + uid | 不合并 | — | 每条独立，避免掩盖开通事件 |
| `system` | room + cmd 派生描述 | ×4 | 32s | `—— 描述 ×N ——` |

实现规则：

1. 合并只在「尚未被虚拟列表消费的入队消息」与「当前最后一行」之间进行，不回溯修改视口上方的历史行。
2. 合并后行数减少，行高按 §7.1 重新测量，锚定按 §7.3 恢复。
3. 「展开」把合并行还原为独立行（会话内有效，不写回偏好）；展开后该行不再参与后续合并。
4. `ui.merge_similar = false` 时全部按原始行渲染；`ui.merge_window_ms` 仅在启用时生效，修改后只对后续合并生效。
5. 合并计数 `N` 显示上限 999，超过仍显示 999（计数本身不封顶）。

### 8.5 设置面板

| 分区 | 内容 | 相关键 / 命令 |
|---|---|---|
| 账号 | 登录态（游客 / 已登录昵称）、扫码登录、退出登录 | `session_status` / `session_qr_start` / `session_qr_poll` / `session_logout` |
| 外观 | 字号滑杆与预设、透明度滑杆、主题三选一、礼物栏模式 | `ui.font_scale` / `ui.opacity` / `ui.theme` / `ui.gift_panel_mode` |
| 滚动 | 自动跟随、悬停暂停、合并相似、合并窗口 | `ui.auto_scroll` / `ui.pause_on_hover` / `ui.merge_similar` / `ui.merge_window_ms` |
| 过滤 | 关键词、模式、告警、UID 列表、类型白名单、粉丝牌下限 | `filter.*` |
| 缓冲 | 本会话缓冲上限 | `history.buffer_rows` |
| 关于 | 版本、数据目录 | `app_info` |

面板只展示上表键，UI 不新增键名；读写在 Tauri 模式下经 `prefs_get` / `prefs_set`（写接受部分键值补丁，未知键或非法值返回 `BAD_REQUEST`）。「手填 Cookie」在本设计中即**直接编辑数据目录下的 `config.toml`**（权限 0600，明文），UI **不提供** Cookie 输入框，只提供打开数据目录的入口；设置面板不回显任何凭据值（契约 §4.1）。

## 11. 空态与错误态

| 状态 | 触发条件 | 聊天流区域 | 提示 | 可用操作 |
|---|---|---|---|---|
| 未登录（游客） | `session_status` 为游客 | 正常渲染 | 细横幅「游客模式：部分消息字段不可见」 | 扫码登录、打开数据目录手填 Cookie |
| 登录中（扫码） | `session_qr_start` 已发起、未完成 | 不受影响 | 弹层显示二维码与轮询状态 | 取消、刷新二维码 |
| 连接中 | 连接请求已发出 | 骨架 3 行 + 「连接中…」 | 房间头黄点 | 断开（刷新按钮禁用） |
| 已断开 | 非主动断开的连接中断 | 保留已渲染行，不再新增 | 横幅「已断开，第 N 次重连，Xs 后重试」 | 刷新（立即重连）、断开 |
| 连接失败 | 认证回应 `code != 0` 或上游错误 | 保留已渲染行 | 横幅「连接失败」+ 原始 code | 刷新、检查登录态 |
| 直播未开始 | 房间 `live_status == 0` | 保留已收消息 | 房间头显示「未开播」 | 保持连接等待开播 |
| 房间无消息 | 过滤后行数为 0 且会话缓冲为空 | 居中文案「暂无消息」 | 无 | 检查过滤、刷新连接 |
| 全部被过滤 | 原始行数 > 0 且过滤后为 0 | 居中文案「全部消息被过滤」 | 无 | 「恢复全部类型」、打开过滤面板 |
| 礼物栏空态 | `separate` 且会话内无礼物 | — | 「本场暂无礼物」 | 切换为 `merged` |
| 表情分组空 | 该 `package_kind` 返回空 | — | 「该分组暂无可用表情」 | 切换分组 |
| 发送失败 | `SendOutcome != ok` | 保留现有内容 | 见 §6.5 文案表 | 按 §6.5 保留草稿并重试 |
| 举报失败 | `chat_report` 返回错误 | 不受影响 | 弹层内显示原始 code 与 message | 重试、取消 |
| IPC 错误 | 任意命令返回错误 | 保留现有内容 | 显示原始 `code` 与 `message` | 「重试」；未知 code 不改写语义 |

错误文案不猜测上游细节；未知错误显示上游原始 `message` 文本。IPC 错误形状与命令清单以 `ipc.md` 为准。

## 14. 一致性约束

1. 本文出现的 IPC 命令、事件名以 [`ipc.md`](ipc.md) 与契约 §7 为准；六种 `kind`、`Message` / `RoomSession` / `Emote` / `FollowedRoom` / `SendOutcome` 字段以契约 §5 为准；偏好键名、类型与默认值以契约 §8 为唯一权威清单——UI 不新增、不重命名，也不把非 §8 状态写入 `prefs.json`。
2. 时间统一按 UTC 毫秒（`ts`）传输，界面按本地时区渲染（`HH:mm:ss`）；跨天时在时间前补日期。
3. 新增 `kind`、调整过滤求值顺序或调整偏好键用法时，必须同步更新本文与 `CHANGELOG.md`；若需新增偏好键，先改契约 §8 再改本文与 `ipc.md`。
